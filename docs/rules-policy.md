# v1 规则与行为澄清

本文档记录在架构审查后明确下来的 v1 行为。它用于补足 `SPEC.md` 中未唯一确定的细节；若与 `SPEC.md` 的明确要求冲突，应停止并请求确认，而不是静默覆盖。

## 1. 规则基线

核心 No-Limit Texas Hold'em 机械规则以 Poker TDA 2024 中与无限注 Hold'em 相关的规则作为实现基线；本项目在 Session、补筹码、掉线、旁观、房主等朋友局产品行为上以 `SPEC.md` 和本文档为准。

关键规则固定如下：

- 最低加注额基于当前下注轮中最近一次/最大的完整有效 bet 或 raise 增量。
- 单个不足完整加注的短码 All-in 不会自动重新开放已经行动过玩家的加注权。
- 多个短码 All-in 累计后，如果某已行动玩家再次面对的新增金额达到至少一个完整 bet/raise，则其加注权重新开放；此时最低加注增量仍以最后一个完整有效 bet/raise 为准，不以短码 All-in 的增量重置。
- 每个 Side Pot 独立结算。
- 平分底池出现整数余筹码时，从 Dealer Button 左侧开始，在该底池有资格且并列获胜的玩家中按座位顺序分配 Odd Chip。
- Heads-up 时 Button 同时为 Small Blind；Button preflop 先行动，之后各街最后行动。
- 玩家筹码不足以支付完整盲注时，投入其全部剩余筹码作为部分盲注 All-in。

## 2. 旁观席与离座

牌桌最多存在 2 名“已连接但未坐下”的旁观者。

区分两个动作：

- `离座旁观`：玩家保留当前 Session 身份、筹码和账本，但释放座位并成为旁观者；必须存在空旁观席。如果 2 个旁观席已满，则不能执行“离座旁观”。
- `离开牌桌`：玩家退出当前连接，不占旁观席；掉线/身份恢复仍按 `SPEC.md` 处理。

离座后重新坐下不得再次领取初始 100。

## 3. 房主

- 当前没有房主时，第一个成功进入牌桌的人成为房主；房主可以处于旁观状态，不要求必须坐下。
- 房主断线后给予 60 秒重连宽限。宽限内重连则保留房主。
- 超过 60 秒仍离线，则将房主转给在线玩家：优先选择已坐下玩家，再选择旁观者；同类中选择当前连续在线时间最长者。
- 若同类玩家的连续在线起点完全相同，则按稳定的 `playerId` 字典序选择，不使用随机数。
- 若无人在线，则暂时没有活跃房主；之后第一个重新连接的人取得房主。
- 已经完成房主转移后，旧房主回来不会自动夺回房主。
- 房主主动“离开牌桌”属于明确退出，不适用 60 秒宽限；系统立即按同一候选顺序转移，无候选时立即设为无房主。
- 房主主动转让立即生效，并取消旧房主对应的任何自动转移计时。

## 4. 三种不同的“60 秒/长期身份”概念

不得混淆：

1. `快速自动重连窗口`：约 60 秒，用于误关页面、刷新、瞬断后尽量无感恢复。
2. `掉线行动等待`：轮到掉线玩家时最多等待 60 秒，之后自动 Fold。
3. `身份恢复凭证`：不因 60 秒到期而失效；在当前 Session 仍有效时，即使数分钟后重新打开并再次输入原昵称，只要浏览器仍持有原凭证，就恢复原玩家记录。

Session 结束后，新 Session 重新要求昵称进入；旧 Session 身份不得自动领取新 Session 的初始筹码。

Session 手动或自动结束时，服务端立即撤销该 Session 的恢复凭证、清空当前座位/在线/房主状态，并断开旧身份连接。旧 cookie 即使仍有浏览器有效期，也不能恢复到新 Session。新聚会重新输入昵称并获得新的 Session 范围身份；昵称唯一性随新 Session 重置，旧 playerId 只保留在历史总结中。

## 5. 多设备

同一玩家身份只允许一个健康的活动连接。

- 若旧连接仍在线且健康，后来的设备/连接不得接管该玩家身份，应拒绝重复控制。
- 若旧连接已经断开或被判定失效，合法重连可以恢复原身份。
- 任何时刻不得出现两个设备同时控制同一玩家。

## 6. Session、开始游戏与下一手

三个概念保持独立：

- `开始本场`：创建新的 Session，并为当时已坐下且首次参与该 Session 的玩家发放初始 100；此时尚未发牌。
- `开始游戏`：在当前 Session 中开始第一手牌。
- `开始下一手`：第一手之后，由房主逐手手动开始。

Session 已开始后才第一次坐下的新玩家，在首次坐下时获得该 Session 的初始 100，并从下一手开始参与。

v1 的“本场统计”只要求筹码相关统计：初始、补充、人工调整、最终筹码、净结果，以及必要的手数/时间元数据；不做 VPIP、PFR 等扑克数据分析。

## 7. 人工筹码调整

- 只能在两手之间执行。
- 只接受整数筹码。
- 负调整后筹码不得低于 0；否则拒绝操作。
- 每次调整必须进入账本并记录操作者与时间。

## 8. 零筹码玩家

- 0 筹码玩家仍可保留座位。
- 在未补充筹码前，不参与下一手、不发牌、不收盲注。
- 在两手之间补充 +100 后，从下一手恢复参与。

## 9. 每手参与资格与 Button/Blind

每手开始时重新计算 eligible players：

- 已坐下
- 当前在线
- 筹码 > 0

只有 eligible players 参与该手。Dealer Button、SB、BB 在 eligible players 中按座位顺序推进；离线、零筹码、旁观者直接跳过。

玩家重新上线或补充筹码后无需等待大盲位，也不追缴错过的盲注，从下一手正常重新进入。

## 10. 手牌历史与 Session 历史

- 手牌详细历史保留全站最近 20 手，跨 Session 计算；每条记录必须包含 Session 标识/日期。
- 超出最近 20 手的详细 Hand 记录可清理，不要求永久保存。
- Session 总结单独保留最近 20 场，即使该场的详细手牌已经被清理，Session 最终筹码结算仍保留。

## 11. 被踢玩家重新加入

“踢人”不是封禁。

- 踢出时断开其连接并释放座位。
- 旧浏览器的活动连接凭证应被撤销，防止它立即继续控制。
- 玩家记录、筹码账本和本场统计不得因为被踢而消失。
- 同一昵称之后允许重新进入并恢复该 Session 对应的玩家记录，服务器为其签发新的连接/恢复凭证。
- 不允许通过“被踢再加入”重新领取初始 100 或复制筹码。

## 12. All-in 的内部动作语义

历史和规则引擎不能只保存一个模糊的 `ALL_IN` 动作。

All-in 必须保留它在规则上的真实语义，例如：

- all-in call
- all-in bet
- all-in raise

可以通过动作类型 + `isAllIn` 标志实现，也可以使用等价的明确表示，以确保最低加注和重新开放行动权计算正确。

## 13. 主动展示手牌

玩家在无需 Showdown 即获胜后选择“展示手牌”时，v1 统一展示两张底牌，不提供只展示一张的功能。

## 14. 房主强制 Fold

不设置“在线玩家挂机多久后自动允许强制 Fold”的客观计时门槛。房主按钮始终作为人工朋友局管理能力存在；使用后记录一条管理审计事件。

v1 中房主强制 Fold 只能针对当前行动且尚未 Fold/All-in 的玩家。主动离开、踢出、掉线行动超时和房主强制 Fold 都通过独立于普通玩家行动的管理 Fold 路径执行，并分别记录 `EXPLICIT_LEAVE`、`KICK`、`DISCONNECT_TIMEOUT`、`HOST_FORCE_FOLD`；记录包含 Hand ID、目标、原因、顺序以及适用时的操作者，不包含底牌或身份凭证。

## 15. 快捷表情限流

默认行为：

- 同一玩家在滚动 1 秒窗口内最多成功发送 4 个快捷表情。
- 第 5 次过快尝试不发送表情，并触发 1 秒隐藏 CD。
- CD 期间继续点击时显示一次“你急了”彩蛋提示；同一次 CD 内不重复弹出大量提示。
- CD 结束后恢复正常。

阈值和 CD 必须集中配置，后续可轻松修改。

## 16. Pot 快捷下注按钮

快捷按钮只是 UI 便利功能，不改变扑克合法下注规则。

约定：

- 无需 Call 时，`x Pot` 以当前服务器权威底池金额的 x 倍作为目标下注量。
- 面对下注时，先计算 Call 后的底池，再以该金额的 x 倍作为 raise 增量，生成“加注至 X”的目标。
- 因筹码只能为整数，计算结果向下取整。
- 计算结果若低于服务器最低合法 Raise，则 UI 使用最低合法 Raise；若超过玩家剩余筹码，则只能形成 All-in。
- 最终目标始终由服务器重新验证，客户端快捷按钮不是规则权威。

## 17. 部署与数据库

部署平台暂不在 Milestone 1 决定。

本地开发可使用 SQLite。进入持久化里程碑前必须确定部署目标：若单实例服务器具备可靠持久磁盘，可继续 SQLite；若部署环境文件系统是临时的，则在正式持久化设计落地前选择 PostgreSQL。

## 18. 实时生命周期计时

- 轮到离线玩家时开始独立的 60 秒行动等待；重连、行动人变化、Fold、手牌完成或新 Hand 都会取消旧计时。回调执行前必须重新核对 Hand ID、当前行动人和在线状态。
- 房主断线宽限是另一条独立的 60 秒计时，不影响恢复凭证寿命。
- 活跃 Session 全员连续离线 30 分钟后自动结束；任意人重连即取消并重新计算连续窗口。截止时若仍在牌局中，只标记待结束，牌局通过掉线 Fold 正常完成后再结束 Session。
- All-in Runout 的第一段公共牌也等待配置间隔；生产默认每 750ms 依次推进 Flop、Turn、River，每段独立广播。旧 Hand 的回调不得影响新 Hand。
- 所有时间由可注入的统一时钟/调度器管理；测试使用假时钟，不等待真实 60 秒或 30 分钟。
